## 2. Feature A — repetition: DEF chunk + instances (`<use>` re-invented)

**Semantics ported from SVG `<use>`**: a *template* is a named list of elements (encoded exactly like GEOM elements, styles resolved by index); an *instance* is a reference placed in document order with either a translate-only offset (SVG `<use x y>` semantics, the common case) or a full matrix (SVG `transform` semantics). Effective geometry = instance transform ∘ template element transforms ∘ points.

**Container**: new chunk `DEF (0x06)`, present before GEOM (tag order stays ascending; backward references only — INV-10 topology preserved).

```
def-chunk   = %x06 chunk-size def-body
def-body    = tmpl-count *template                ; count ≤ remaining (norm., INV-2)
template    = tmpl-id elem-count *element         ; element = GEOM element encoding (§6)
tmpl-id     = varuint                             ; unique (norm.: duplicate → reject)
```

**Instances in GEOM**: shape type `8` (fits the 4-bit shape field):

```
instance    = inst-byte tmpl-id transform
inst-byte   = u8          ; bit0: 0 → translate-only (tx,ty) · 1 → full matrix (6 varint)
                          ; bits1–7 reserved 0 (norm.)
translate   = 2varint     ; tx, ty — absolute (SVG <use> x/y semantics)
matrix      = 6varint     ; instance matrix, pre-multiplied over template matrices
```

Instances carry **no style reference**: they render with the template's internal styles (v0.2 limitation, documented). Instances ARE elements: paint order, A11Y label indices and per-instance labels work unchanged.

**Encoding-side heuristic (non-normative)**: any conforming encoder may choose templates freely; the reference encoder hashes canonicalized subtrees and promotes those appearing ≥ 2 times when the cost model favors it.

## 3. Feature B — gradients: GRAD chunk + style extension

New chunk `GRAD (0x07)`, indexable like STYLE; style entries reference gradients:

```
grad-chunk  = %x07 chunk-size grad-count *gradient      ; count ≤ remaining (norm.)
grad-count  = varuint
gradient    = grad-type units spread stop-count *stop [grad-matrix]
grad-type   = u8              ; 0 linear · 1 radial                      (norm.: else reject)
units       = u8              ; 0 objectBoundingBox · 1 userSpaceOnUse
spread      = u8              ; 0 pad (only value in v0.2)               (norm.: else reject)
stop-count  = varuint         ; ≥ 1                                      (norm.: 0 → reject)
stop        = offset-u8 rgb24 [alpha-u8]   ; alpha present iff grad-type byte declares it —
                                              ; declared per gradient in a flags u8 (see below)
grad-matrix = 6varint         ; present iff flags bit0 = 1 (gradientTransform)
flags       = u8              ; bit0 has-matrix · bit1 stops-have-alpha
```

`objectBoundingBox` coordinates and offsets quantize to **u8** (0–255 over the unit box / over [0,1]) — a 2-stop linear OBB gradient costs ≈ **16 bytes** (vs ~250 in SVG text). `userSpaceOnUse` coordinates are varint-fixed. Styles extend: `style_byte` bits 0–1 value `3` = *fill is gradient*, followed by `grad-ref = varuint` (bit0 = has-gradient-matrix override, bits≥1 = gradient index).

## 4. Feature C — command-run packing (MVT CommandInteger port)

Path commands become runs: `run = varuint = (count << 3) | cmd-id`, followed by `count` point-sets (M→1 point, L→1, C→3, Q→2, A→arc+point, Z→0). Single commands still cost 1 byte (count = 1 → values 8–13). Attacking the measured ~12% command-byte cost. Normative: `cmd-id ≥ 6 → reject` (as v0.1.1); `value < 8 → reject` (count ≥ 1 by construction — DEC-5).

## 5. Grammar extensions (ABNF deltas over the v0.1.1 audit-brief §4)

```
version-2   = %x02                                   ; version byte is 2 for files using §3–§5
flags       =/ bit4 HAS_DEF · bit5 HAS_GRAD          ; announced like HAS_A11Y/HAS_STYLE
def-chunk   = %x06 ...                               ; as §2
grad-chunk  = %x07 ...                               ; as §3
element     =/ instance                              ; shape type 8 added to the union
command     = command-run                            ; replaces per-command byte (v2 files)
style-byte  =/ fill/stroke type 3 = gradient ref     ; as §3
```

Everything else — header layout, varuint alphabet (7 bytes/49 bits), zigzag deltas, EOF guards, count bounds, chunk skipping — is **unchanged** (INV-1…INV-12 continue to apply verbatim).

## 6. New invariants

- **INV-13 — Reference integrity, acyclic by construction.** Every `tmpl-id` and gradient index must resolve; duplicate template ids rejected. Templates **cannot contain instances** (flat templates only) → expansion is a bounded loop, decoder call depth stays constant (INV-11 undisturbed), cycles are impossible by grammar.
- **INV-14 — Expansion budget (the template bomb guard).** Decompression-bomb analog: `Σ (instances × template elements)` must not exceed **1,000,000 emitted elements** (DEC-6). Verified at decode before expansion. Hostile test planned: 30k instances × 1k-element template from a ~100 KB file must reject.
- **INV-15 — Gradient bounds.** stop-count ≥ 1 and ≤ remaining; units/spread/type outside the v0.2 vocabulary → reject; out-of-range gradient index → **reject** (strict; legacy v1 style-index tolerance unchanged for compatibility — DEC-4).
- **INV-16 — Version discipline.** Files using §2–§5 features carry version byte `2`; v0.1.1 decoders reject them cleanly at the header (better than mid-stream misparse — the v0.1 style reader would misread fill-type 3). v0.2 decoders accept versions 1 and 2. Format history: v1 files remain valid forever.

## 7. Threat model additions (mapped to invariants)

| attacker goal | guard |
|---|---|
| template bomb (expansion blowup, XML-bomb analog) | INV-14 budget check before expansion + hostile test planned |
| dangling references (tmpl-id / gradient index) | INV-13 / INV-15 strict rejects |
| instance storms (CPU) | INV-2 count bounds apply to DEF and instance counts; expansion is a linear loop (INV-11) |
| grammar confusion on new types | strict type/unit/spread vocabularies (INV-15); reserved bits normative-zero |

## 9. Open decisions for the gate (DEC)

- **DEC-1** — instance kinds: translate-only + full matrix as proposed, or matrix-only? (Proposal: both; translate-only is the size-critical common case.)
- **DEC-2** — gradient `units`: include `userSpaceOnUse` in v0.2 or OBB-only? (Proposal: both; OBB-u8 is the tiny common case.)
- **DEC-3** — version byte `2` for v0.2-feature files (proposal) vs flag-bit approach. (Proposal rationale: clean rejection by old decoders, no mid-stream misparse.)
- **DEC-4** — legacy v1 style-index tolerance kept; new v2 files get strict reference checks. (Proposal.)
- **DEC-5** — command-run `value < 8` → strict reject (proposal) vs lenient count=1.
- **DEC-6** — expansion budget value: 1,000,000 emitted elements (proposal).
- **DEC-7** — gradients without alpha vs with (flags bit): proposal flags bit1, alpha optional per gradient.

## 10. Explicitly NOT in v0.2 (deferred, with triggers)

- Entropy stage (grammar-informed codes / rANS) — **DD-4 trigger**: measured gap to svg+brotli > 10% on any target class after REP lands.
- `<text>`, clip/mask, filters, CSS — unchanged from v0.1 scope.
- Organic-class geometry modeling (adaptive quantization / curve fitting) — v0.3.
- Template style overrides (recoloring instances) — v0.3 candidate (the `currentColor` use case).
